# মাইগ্রেশন যাচাই — লোকাল Postgres

এই প্রজেক্টের মাইগ্রেশন হাতে চালানো হয় Supabase SQL এডিটরে। অর্থাৎ কোনো
মাইগ্রেশন ফাইল **একজন মানুষ চালানোর আগে কখনো চলে না** — আর যে ফাইল কখনো চলেনি,
সেটা কোড নয়, অনুমান। এই ফোল্ডারটা অনুমানটাকে ফলাফলে বদলায়।

```bash
bash supabase/tests/run-local-checks.sh
# অন্য কোনো মাইগ্রেশন হলে:
bash supabase/tests/run-local-checks.sh supabase/migrations/2026XXXX_....sql

# Sprint 5 — কর্মঘণ্টা, ছুটি, রিশিডিউল, রিমাইন্ডার (৫৪টা চেক)
bash supabase/tests/run-sprint5-checks.sh

# Sprint 5.1 হার্ডেনিং — অ্যাপয়েন্টমেন্ট টাকার হিসাবে (৭৮টা চেক)
bash supabase/tests/run-sprint5-hardening-checks.sh
```

স্ক্রিপ্টটা একটা **অস্থায়ী লোকাল Postgres ক্লাস্টার** বানায়, `fixture.sql` দিয়ে
আসল স্কিমার প্রয়োজনীয় অংশটুকু (shops, chairs, services, profiles,
chair_service_stats, `auth.uid()`, `is_shop_owner()`) দাঁড় করায়, তারপর আসল
মাইগ্রেশন ফাইলটা চালায় — শেষে ক্লাস্টারটা মুছে ফেলে।

**কোনো Supabase প্রজেক্ট স্পর্শ করে না।**

## কী কী যাচাই হয়

| ধাপ | কী দেখে |
|---|---|
| গঠন | RLS চালু, পলিসির সংখ্যা, কনস্ট্রেইন্ট, ইনডেক্স, RPC-র SECURITY মোড |
| ইনসার্ট ট্রিগার | `ends_at` সার্ভার হিসাব করে, দাম জমাট, অতীত/ক্রস-শপ/সময়ের বাইরে reject |
| স্ট্যাটাস মেশিন | অবৈধ ট্রানজিশন reject, DONE চূড়ান্ত, ইতিহাস পুনর্লিখন অসম্ভব |
| আইসোলেশন | **আসল non-superuser রোলে** — অন্য দোকানের মালিক ০ সারি দেখে |
| স্লট RPC | বুকিং করলে ওভারল্যাপিং স্লট সরে, বাতিল করলে ফিরে আসে |
| কনকারেন্সি | ৮টা সমান্তরাল ক্লায়েন্ট একই স্লট চায় → ঠিক ১টা টেকে |

হার্ডেনিং স্ক্রিপ্টটা (`run-sprint5-hardening-checks.sh`) বাড়তি যা দেখে:

| ধাপ | কী দেখে |
|---|---|
| `completed_at` | DONE-এ বসে, IN_PROGRESS-এ বসে না, একবার বসলে আর সরে না |
| ঐতিহাসিক দাম | সার্ভিসের রেট বদলালেও পুরনো অ্যাপয়েন্টমেন্টের দাম/স্ন্যাপশট অপরিবর্তিত |
| টাকার সম্পর্ক | অ্যাপের তিনটে কোয়েরি (ইনকাম, ক্যাশবুক, বাকির খাতা) হুবহু SQL হিসেবে |
| লিস্ট ফিল্টার | today / upcoming / completed / cancelled / provider / তারিখ-রেঞ্জ |
| আইসোলেশন | **আসল non-superuser রোলে** — B-এর আয়ে A-র এক টাকাও নেই |
| বকেয়া রিমাইন্ডার | মালিক-চেক, ২৪ ঘণ্টার কুলডাউন, বাকি-নেই, অ্যাকাউন্ট-নেই |
| সেলুন রিগ্রেশন | `serials` টেবিল, তার ট্রিগার, `send_due_reminder`, `total_amount` লেখা — সব আগের মতো |

সেলুন রিগ্রেশনের জন্য স্ক্রিপ্টটা নিজেই একটা ছোট `serials` টেবিল বানায় (শেয়ার্ড
`fixture.sql`-এ নয়, কারণ বাকি দুটো স্ক্রিপ্টের ওটা লাগে না) — যাতে "কিউ আগের
মতোই চলে" কথাটা একটা আসল সারিতে প্রমাণ হয়, অনুপস্থিত টেবিল নিয়ে দাবি না হয়।

আইসোলেশনের ধাপটা `app_user` নামে একটা আলাদা রোল বানিয়ে চালায়, কারণ
**superuser আর টেবিলের মালিক RLS বাইপাস করে** — postgres ইউজারে পরীক্ষা করলে
সব পলিসি "পাস" দেখাত, অথচ কিছুই প্রমাণ হতো না।

## দরকার

- `postgresql-16` বাইনারি (`/usr/lib/postgresql/16/bin`)
- একটা non-root ইউজার — Postgres root হিসেবে চলতে অস্বীকার করে।
  ডিফল্ট `postgres`; বদলাতে `RUNAS=youruser bash ...`

## সীমা — যা এটা প্রমাণ করে না

লোকাল ক্লাস্টার ≠ তোমার Supabase ইনস্ট্যান্স। ফিক্সচারটা আসল স্কিমার **নকল**,
হুবহু কপি নয় — বাস্তব টেবিলে বাড়তি কলাম, ট্রিগার বা পলিসি আছে যা এখানে নেই।
তাই এটা পাস করা মানে "মাইগ্রেশনটা যুক্তিতে ঠিক", **"তোমার ডেটাবেসে চলবে" নয়**।
আসল যাচাই এখনো SQL এডিটরে ফাইলের শেষের ভেরিফিকেশন ব্লক চালানো।
